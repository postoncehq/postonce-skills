# Hook vault

`references/hooks.json` holds 100 hook templates. Each one is the opening line of a real post with a large audience, turned into a fill-in template. The same library is browsable at [postonce.to/free/hook-vault](https://postonce.to/free/hook-vault).

Each entry has: `template` (the `[bracketed]` parts get replaced), `type`, `works_on` (TikTok, Reels, Shorts, LinkedIn, X), `real_example` (the original line), `source` (link to the post) and `views` when known.

## How to write hooks with it

1. **Know the post first.** Get the topic, the audience, the platform, and the one payoff the post delivers. A hook is a promise; it must match what the post actually gives.
2. **Pick 3 templates from different types** that fit the platform (`works_on`) and the payoff. Types include `contrarian`, `number_list`, `secret_insider`, `howto_promise`, `result_proof`, `bold_claim`, `story`, `mistake`, `comparison`, `question` and more. Different types give the user a real choice.
3. **Fill the brackets with the user's specifics:** real numbers, real names, the real outcome. Never invent a result, a follower count or a figure the user didn't give you. If a template needs proof they don't have, pick another template.
4. **Fit the format.** Video: under about 12 words, said and shown on screen in the first 2 seconds. LinkedIn: the first two lines before "see more". X, Threads and Bluesky: the whole post often is the hook.
5. **Show the source.** For each hook, add the `real_example` it was modeled on, so the user sees the pattern working.

## Output

Three hooks, each with its type, the filled line, and the original example it came from. Recommend one and say why in a sentence. Offer to film-test all three (same video, three openings), then keep the one that holds viewers longest.

If the user wants to publish, write the rest of the post with the `post-everywhere` skill and schedule it through PostOnce.
